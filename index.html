相比老的 CodePush，好在哪里

CodePush 是微软的热更新服务，所在的 App Center 已于 2025 年 3 月停止服务；继续使用只能依赖社区维护的自建版本。

1不会被停服卡脖子

平台与 SDK 全部自研自建，代码和数据都在自己手里，可随 React Native 新版本持续升级。

CodePush：官方服务已停，SDK 不再更新

2包内容加密，防止源码泄露

每个版本一把随机密钥加密，CDN 上的文件即使被下载也无法还原 JS 代码；同时强制签名，防止被篡改。

CodePush：包是普通压缩文件，签名为可选项

3开发零操作，网页控制发布

提交代码自动打包到测试通道，网页也可选任意提交打包，不需要开发在本机执行命令。

CodePush：需要开发在本机或自建脚本执行发布命令

4上线必须审批

推到正式环境必须由发布负责人在网页审批，申请人不能自审，所有操作留记录。

CodePush：有权限即可直接推广，无审批流程

5精细化排查

白名单设备可提前体验；按设备 ID 查询检查与安装记录，快速定位个别用户问题。

CodePush：只有汇总数字，无法查单台设备

6国内速度与数据合规

服务与 CDN 部署在国内云，下载更快；设备数据不出境。

CodePush：服务器在海外，国内访问慢、不稳定

7App 与 H5 一个平台发布

iOS、Android、H5 共用审批、灰度、回退与数据统计，团队只需学一套流程。

CodePush：只支持 React Native App，H5 灰度需另找方案

与 CodePush 同等具备：按比例灰度、新包崩溃自动回滚、Hermes 字节码、可选/立即/下次启动三种生效方式。
